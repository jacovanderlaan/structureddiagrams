The idea

One model, many notations

Different readers need different pictures of the same thing. An executive needs a context diagram; an engineer needs column-level lineage; an auditor needs to know what feeds what. Hand-drawn, that is four artifacts to maintain. Generated, it is four views of one source.

Mermaid

Text-first, diffable, renders in Markdown and Git. The pragmatic default when the diagram belongs beside the code.

draw.io

Where people actually sketch. Worth generating into — and worth parsing back out of, so the sketch is not a dead end.

PlantUML & Graphviz

Layout engines that do the hard part. You describe what connects to what; they decide where it goes.

yEd

For the large graph nobody can hand-arrange — hundreds of entities, laid out automatically and still readable.

Notation is a rendering choice, not an architecture decision. If switching from Mermaid to PlantUML means redrawing everything, the diagram was never generated in the first place.

The same model, four times

A site arguing that diagrams are generated should not illustrate the claim with a picture of a diagram. So below is the actual thing: one source model, and the four files a generator produced from it. Nothing here was drawn.

The source

Five entities, six relationships — small enough to read whole, rich enough to carry cardinality, a self-reference and a many-to-many.

entities:
  - name: Person
    attributes:
      - {name: person_id, type: int, key: pk}
      - {name: full_name, type: string}
      - {name: mentor_id, type: int, key: fk}
  ...
relationships:
  - {from: Person, to: Organisation, label: works for, from_card: many, to_card: one}
  - {from: Person, to: Person,       label: mentored by, self: true}
  - {from: Talk,   to: Person,       label: given by}

model.yaml — the whole file.

The renderings

Each was produced by the same generator in one pass. The interesting column is the last one.

NotationOutputWhat it proves
Mermaidconference.mmdRenders where the code lives — GitHub, Obsidian, Markdown. Text, so it diffs.
draw.ioconference.drawioOpens and edits in draw.io. Generated output need not be read-only.
PlantUMLconference.pumlA layout engine places the boxes, not a person with a mouse.
yEdconference.graphmlCarries no coordinates at all — auto-layout decides, which is the only way large graphs stay readable.

The Mermaid output, in full — this is what “generated” actually looks like:

erDiagram
    Person }o--|| Organisation : "works for"
    Person }o--|| Person : "mentored by"
    Talk }o--|| Person : "given by"
    Talk }o--|| Room : "scheduled in"
    Attendance }o--|| Person : "by"
    Attendance }o--|| Talk : "of"

The honest part. None of these four is prettier than a diagram a careful person would draw by hand. That is not the claim. The claim is that when the model changes, all four change — and nobody opens a drawing tool.
